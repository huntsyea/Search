# Files

- [Chrome extensions on WKWebExtension](architecture.md) - How Search runs Chrome extensions on Apple's WKWebExtension (macOS 15.4+) — the Extensions controller and installed.json, staggered loading and stale-worker clearing, ExtensionTab/ExtensionWindow adapters, permission policy (granted at install, never extension pages or files), the puzzle-button slot and Search-owned popups, popup windows, and daily store updates.
- [Chrome API shims](chrome-api-shims.md) - How ExtensionShims rewrites each installed extension to inject search-shim.js, which defines Chrome APIs WebKit lacks (bookmarks, history, downloads, sidePanel, offscreen, userScripts, identity, tabGroups…) as native messages answered by Search, gated by the extension's manifest, and mends WebKit/Chrome behaviour differences in messaging and workers.
- [Installing extensions: CRX, Web Store and unpacked](installation.md) - How Search installs Chrome extensions — fetching a CRX3 from Chrome's update service and verifying that its RSA proof's key hashes to the requested id, the Web Store "Add to Search" button, unpacked folders with path-derived ids and Reload, staging and atomic folder replacement, removal and data clearing, and the tests that cover them.
- [Extension native bridges: messaging, sockets, offscreen, capture](native-bridges-and-capture.md) - The native pieces that let Chrome extensions do what WebKit alone can't — Chrome native messaging hosts, a URLSession WebSocket for workers, offscreen documents, screen/camera/mic capture with per-extension consent and the recording pill, externally_connectable pages, and the policy for websites returning to extension pages.
